## Week 5 – Learning Targets

### Next.js Foundations
1. I can explain how Next.js differs from a client-only React application.
2. I can describe when server-side rendering, static generation, or client rendering is appropriate at a high level.
3. I can create a Next.js TypeScript project and identify the main files and folders used by the framework.
4. I can explain how framework conventions influence routing, rendering, and data loading.

---

### Routing
1. I can create application routes using Next.js file-based routing conventions.
2. I can build shared layouts and navigation patterns across multiple pages.
3. I can use dynamic route segments to support parameterized pages.
4. I can explain how route structure affects user navigation and URL design.

---

### Rendering and Data Fetching
1. I can explain the difference between fetching data on the server and fetching data in the browser.
2. I can implement page-level data fetching appropriate to the rendering strategy being used.
3. I can pass fetched data into UI components while preserving type safety in TypeScript.
4. I can handle loading, error, and empty states in a predictable way.
5. I can explain the tradeoffs between freshness, performance, and complexity in data-fetching decisions.

---

### Configuration and Environment Management
1. I can identify common Next.js configuration files and explain their purpose at a practical level.
2. I can use environment variables appropriately for server-only and client-exposed configuration.
3. I can distinguish between build-time and runtime configuration concerns.
4. I can troubleshoot configuration issues that affect routing, rendering, or API access.

---

### React and TypeScript in Next.js
1. I can build reusable Next.js pages and components using the same React and TypeScript discipline established earlier in the cohort.
2. I can type page props, route params, and fetched data structures clearly.
3. I can structure a Next.js application so routing, UI, and data concerns remain understandable.
4. I can test and verify key page behavior before integrating with external APIs.

---

### Agile, Scrum, and Team Workflow
1. I can explain the purpose of Agile delivery and how iterative development differs from large up-front planning.
2. I can describe the roles, events, and artifacts commonly used in a Scrum workflow.
3. I can participate in standups, sprint planning, and retrospectives using clear technical communication.
4. I can break a feature idea into smaller backlog items with understandable scope and acceptance criteria.
5. I can explain how versioned, incremental work supports team delivery and feedback.
