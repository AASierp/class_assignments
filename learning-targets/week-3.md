## Week 3 – Learning Targets

### JSX and React Project Structure
1. I can explain what JSX is and how it relates to JavaScript and rendered UI output.
2. I can create React components that return valid JSX with proper nesting and expressions.
3. I can organize a React project into reusable files and folders that separate components, styles, and supporting logic.
4. I can identify and correct common JSX issues such as missing wrappers, invalid attribute names, and incorrect expression usage.

---

### React Fundamentals: Components, Props, and State
1. I can build functional React components that render predictable UI from inputs.
2. I can pass data into components through props and explain one-way data flow.
3. I can use component state to represent changing UI data over time.
4. I can update state in response to user interactions and explain how those updates affect rendering.
5. I can compose multiple components to create larger interfaces from smaller reusable parts.

---

### React Hooks
1. I can use `useState` to manage local component state.
2. I can use `useEffect` to run side effects at the appropriate times in a component lifecycle.
3. I can explain dependency arrays at a practical level and avoid common side effect mistakes.
4. I can identify when logic belongs in a hook, a helper function, or a separate component.

---

### React with TypeScript
1. I can type React component props clearly and correctly.
2. I can type component state, event handlers, and simple async data structures in React.
3. I can use TypeScript to catch prop mismatches and unsafe state assumptions during development.
4. I can model lists, forms, and component interactions using appropriate TypeScript types.
5. I can maintain readable React code without weakening type safety through unnecessary `any` usage.

---

### UI Component Libraries
1. I can install and use a UI component library within a React TypeScript project.
2. I can read component documentation and apply the correct props, variants, and composition patterns.
3. I can style and configure library components while preserving consistency and accessibility.
4. I can distinguish between reusable design-system components and app-specific components.
5. I can integrate a component library into an application without losing clarity in state and data flow.
