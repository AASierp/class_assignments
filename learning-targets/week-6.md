## Week 6 – Learning Targets

### Relational Data Modeling
1. I can design tables using entities, attributes, primary keys, and foreign keys.
2. I can identify one-to-one, one-to-many, and many-to-many relationships in an application domain.
3. I can use join tables to represent many-to-many relationships.
4. I can apply basic normalization to reduce duplicated data while preserving useful relationships.
5. I can explain how database structure influences API and application data shapes.

---

### SQL Querying
1. I can write `SELECT` queries that return specific columns and rows.
2. I can filter, sort, and limit records using `WHERE`, `ORDER BY`, and `LIMIT`.
3. I can use `INNER JOIN` and `LEFT JOIN` to combine related data across tables.
4. I can use aggregate functions such as `COUNT`, `MIN`, `MAX`, and `AVG` with `GROUP BY`.
5. I can choose query patterns that support common application needs such as lists, details, filters, and summaries.

---

### SQL Data Changes and Integrity
1. I can insert, update, and delete records intentionally using SQL statements.
2. I can explain how foreign keys protect relationships between tables.
3. I can distinguish between required and optional data using `NOT NULL` and nullable columns.
4. I can explain how constraints such as `UNIQUE`, primary keys, and foreign keys protect data quality.
5. I can reason about how database rules and application validation work together.

---

### SQL in a Full-Stack Architecture
1. I can explain how application data moves between a frontend, an API, a backend, and a relational database.
2. I can connect database tables to backend models and API response shapes at a conceptual level.
3. I can explain why backend code controls database access instead of exposing direct database access to the browser.
4. I can troubleshoot whether a data issue is likely coming from the frontend, API, backend logic, or database layer.

---

### REST Fundamentals
1. I can explain REST as a resource-oriented approach to designing web APIs.
2. I can identify how HTTP methods such as `GET`, `POST`, `PUT`, `PATCH`, and `DELETE` are commonly used in REST APIs.
3. I can recognize the relationship between URLs, resources, and actions in a REST-style API.
4. I can interpret common HTTP status codes such as `200`, `201`, `400`, `404`, and `500`.
5. I can explain the difference between request data, response data, and stateless communication in a REST API.

---

### Working with REST from Next.js
1. I can fetch data from REST endpoints in a Next.js application.
2. I can model API request and response shapes in TypeScript for frontend safety.
3. I can handle asynchronous loading, errors, and data transformation when integrating external APIs.
4. I can map REST response data into components without losing clarity or type safety.
