## Week 1 – Learning Targets

### Introduction to Version Control with Git
1. I can verify Git is installed and use Git from the command line.
2. I can initialize a Git repository and understand the purpose of the `.git` directory.
3. I can explain the difference between the working directory, staging area, and repository.
4. I can track repository state using `git status`.
5. I can stage and unstage changes using `git add` and `git reset`.
6. I can create commits, write meaningful commit messages, and explain what a commit represents.
7. I can view and interpret commit history using `git log` and `git log --oneline`.
8. I can compare changes using `git diff`.
9. I can restore files to a previous state using `git restore`.
10. I can manage multiple files within a Git repository and understand how Git tracks changes across files.
11. I can create and use `.gitignore` files to exclude files from version control.
12. I can create, switch between, and delete branches using `git branch` and `git checkout`.
13. I can explain how branches isolate work and compare changes between branches.
14. I can clone a remote repository and push changes to a remote using `git clone` and `git push`.
15. I can use Git-based platforms (such as GitHub) to host repositories and collaborate with others.
16. I can interpret concise status output using `git status -sb`.
17. I can describe and experiment with advanced Git concepts such as merge conflicts, cherry-picking, squashing commits, and rebasing, and explain when each is appropriate.

### Web Fundamentals
1. I can explain how browsers, servers, URLs, HTTP requests, and responses work together to deliver a web application.
2. I can describe the roles of HTML, CSS, and JavaScript in a modern frontend application.
3. I can use browser developer tools to inspect page structure, styles, network requests, and console output.
4. I can distinguish between static content, dynamic behavior, and client-server communication.

---

### HTML Structure and Semantics
1. I can create valid HTML documents with the required document structure and metadata.
2. I can use semantic HTML elements to organize page content in a meaningful and accessible way.
3. I can create links, lists, forms, inputs, buttons, tables, and media elements for common user interfaces.
4. I can explain why semantic markup improves maintainability, accessibility, and collaboration.

---

### CSS Layout and Styling
1. I can apply CSS selectors, classes, and basic styling rules to control presentation.
2. I can use the box model to explain spacing, borders, sizing, and layout behavior.
3. I can build page layouts using flexbox and grid for common responsive patterns.
4. I can use typography, color, spacing, and reusable class patterns to create consistent interfaces.
5. I can debug CSS issues by inspecting computed styles and layout behavior in the browser.

---

### JavaScript Core
1. I can declare variables and use JavaScript primitive and object data types appropriately.
2. I can write conditional logic and looping constructs to control program flow.
3. I can define and call functions with parameters and return values.
4. I can use arrays and objects to store and process application data.
5. I can respond to user interactions by selecting DOM elements and attaching event listeners.
6. I can update page content dynamically with JavaScript based on user input or application state.

---

### JavaScript and Browser APIs
1. I can make HTTP requests from the browser using the `fetch` API.
2. I can work with asynchronous JavaScript using promises and `async`/`await` at a practical level.
3. I can read JSON data from an API response and use it in frontend code.
4. I can distinguish between successful responses, HTTP errors, and network failures when working with API requests.
5. I can update the page based on loading, success, and error states from a browser request.
6. I can use browser developer tools to inspect network requests and troubleshoot frontend API issues.

### JavaScript Debugging
1. I can use `console.log` intentionally to inspect values, control flow, and application state while debugging.
2. I can use browser developer tools to identify JavaScript errors, inspect stack traces, and locate the source of runtime failures.
3. I can use breakpoints and step-through debugging to understand how JavaScript code executes.
4. I can isolate whether a frontend problem comes from DOM selection, event handling, data shape, asynchronous behavior, or network requests.
5. I can explain the difference between syntax errors, runtime errors, and logic errors in JavaScript code.
