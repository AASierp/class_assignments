## Week 8 – Learning Targets

### Spring Fundamentals
1. I can explain the role of Spring in building Java applications.
2. I can identify the responsibilities of controllers, services, repositories, and configuration at a high level.
3. I can create a basic Spring application structure that separates request handling, business logic, and data access.
4. I can explain dependency injection and how it reduces tight coupling between classes.

---

### Building REST APIs
1. I can design REST endpoints that expose clear resource-oriented behavior.
2. I can implement controller methods that handle common HTTP verbs such as `GET`, `POST`, `PUT`, and `DELETE`.
3. I can map incoming request data to Java objects and return structured responses.
4. I can use HTTP status codes intentionally to represent success and failure cases.
5. I can test API behavior by making requests and validating responses.

---

### JPA and Persistence Modeling
1. I can explain the purpose of JPA and how entities map Java objects to relational tables.
2. I can create entity classes with fields, identifiers, and simple relationships.
3. I can use repositories or equivalent persistence abstractions to read and write data.
4. I can explain how object models and relational storage interact through an ORM approach.
5. I can identify common persistence concerns such as entity identity, relationships, and query behavior.

---

### JDBC Fundamentals
1. I can explain how JDBC differs from higher-level persistence abstractions such as JPA.
2. I can describe when direct SQL access may be useful alongside ORM-based approaches.
3. I can read example JDBC-style data access code and explain the flow from query to returned result.
4. I can compare tradeoffs between lower-level SQL control and higher-level persistence convenience.

---

### Postgres and Application Data
1. I can explain the role of PostgreSQL as the relational database used by the backend application.
2. I can configure a Spring application to connect to a Postgres database using environment-based settings.
3. I can inspect tables and data in Postgres to verify that application reads and writes are working as expected.
4. I can distinguish between application-layer issues and database-layer issues when troubleshooting persisted data behavior.
5. I can explain how Postgres, JDBC, and JPA fit together in the backend data-access workflow.
